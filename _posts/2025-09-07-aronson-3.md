# Introduction

In [Part 1](https://ikavodo.github.io/aronson-1/) and [Part 2](https://ikavodo.github.io/aronson-2/) we explored the fascinating world of self‑referential Aronson sequences. We defined two sets – the forward Aronson set ($A_T(\to)$) and the backward one ($A_T(\gets)$) – and asked: **what is their intersection?** We found a few singletons, but the general question remained open.

To answer it definitively, we need a complete list of all valid Aronson sequences up to a given length. For length ≤ 5 we can actually enumerate them – but only if we drastically prune the search space. This post walks through the mathematics and algorithms that made that enumeration possible, and finally reveals the long‑awaited intersection counts.

---

## Why the Search Space Is Finite (per Length)

A valid Aronson sequence of length $n$ is an increasing list of positive integers $i_1 < i_2 < \dots < i_n$ such that the sentence

> $\Omega$ is the [ord($i_1$)], [ord($i_2$)], … [ord($i_n$)] letter

(ignoring spaces and punctuation) has the letter $\Omega$ exactly at positions $i_1, i_2, \dots, i_n$.

The crucial observation: **the largest index $i_n$ cannot be arbitrarily large**. Why? Because the sentence itself must contain that index as a character position. The total length of the sentence is:

- Fixed part: $C = \|\text{"Ωisthe"}\| + \|\text{"letter"}\| = 12$  
- Variable part: the concatenated ordinal strings (stripped of spaces, commas, hyphens).

If the largest index is $M$, then the sentence length $L$ satisfies

$$
L = C + \sum_{k=1}^n \ell(i_k)
$$

where $\ell(i)$ is the length of the stripped ordinal representation of $i$ (e.g., $\ell(11)=8$ for `"eleventh"`). Since $i_k \le M$, we have $\ell(i_k) \le \ell_{\max}(M)$, the maximum ordinal length among numbers $\le M$. Therefore

$$
L \le C + n \cdot \ell_{\max}(M).
$$

But $M$ itself is a position in the sentence, so $M \le L$. Combining,

$$
M \le C + n \cdot \ell_{\max}(M). \tag{1}
$$
The function $\ell_{\max}(M)$ is non‑decreasing and increases only when $M$ crosses a power of ten (because longer ordinals appear only when we reach a new digit length). Hence (1) gives an implicit upper bound on $M$ for a fixed $n$. For $n=5$, this bound is about $M \le 92$, so the search space is $\binom{92}{5} \approx 2.7\times10^7$ candidate sets – still large, but manageable with clever pruning.

---

## Finding the upper bound

To make the bound precise we need $\ell_{\max}(d)$ for each digit length $d$. I computed this empirically by scanning all numbers up to $10^d$ for $d = 1$ to $10$:

```python
def max_ordinal_length(d):
    # d = number of digits (e.g., d=2 for 10..99)
    max_len = 0
    for n in range(10**(d-1), 10**d):
        os = num2words(n, ordinal=True).replace(" and", "")
        os = os.replace(", ", "").replace(" ", "").replace("-", "")
        max_len = max(max_len, len(os))
    return max_len
```

The resulting table (stored as `ORD_LEN`) is:

| digits | max ordinal length |
|--------|---------------------|
| 1      | 7                   |
| 2      | 14                  |
| 3      | 26                  |
| 4      | 39                  |
| 5      | 45                  |
| 6      | 56                  |
| 7      | 69                  |
| 8      | 75                  |
| 9      | 87                  |
| 10     | 99                  |

## Backtracking with Pruning

We generate sequences in **increasing order** (so each candidate is a sorted list). The recursive function tries to extend a partial sequence by adding the next smallest available number that could possibly lead to a valid full sequence. At each step we maintain a set of *remaining* numbers (all integers from 1 up to the current upper bound that are not already in the sequence and not known to be impossible).

The core of the pruning is a **metric** that estimates whether the current partial sequence can ever be completed. We compute the mean of the current indices and the maximum deviation from that mean:

$$
\text{metric} = \max_{x \in \text{current}} |x - \text{mean}|
$$

Intuitively, if the indices are too spread out, the later ones will be too large to fit in the sentence, given the slow growth of ordinal lengths. The heuristic compares the current deviation to an **upper bound** derived from $n$ and the current digit key:

```python
UPPER_METRIC_BOUND(n, key) = ceil((log2(n) + 1) * ORD_LEN[key])
```

This heuristic is remarkably effective: it cuts the search space by orders of magnitude.

## Results
Using the backtracking algorithm with pruning (and parallelised across multiple cores) and verification, I was able to enumerate **all** valid forward and backward Aronson sequences of length up to 5. The number of enumerated sequences of length n (n indices) per set are:

| n | forward | backward | intersection |
|---|--------:|---------:|-------------:|
| 1 | 8       | 7        | 2            |
| 2 | 73      | 67       | 4            |
| 3 | 955     | 771      | 7            |
| 4 | 16205   | 13113    | 8            |
| 5 | 336890  | 279981   | 37           |

Compared to the forward/backward sets, the intersection is *extremely* sparse, yet seems to grow monotonically with *n*. We can assume that it eventually also begins to grow exponentially, though whether this really happens remains unclear without intensive computation or further proof (if you have an idea for how to do this- let me know!).
